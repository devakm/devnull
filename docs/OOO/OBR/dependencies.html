Dependencies

These are the runtime components a player needs to install themselves. None of them are bundled in the OOORF release archive — install them separately before deploying OOORF.

Required

Oblivion Remastered

The base game. Install via Steam, Game Pass, or your platform of choice.

MagicLoader

OOORF ships its plugin in two complementary forms: a single Oscuro's_Oblivion_Overhaul.esp plus a per-record-type JSON config family containing localization strings and map loading instructions under …\ObvData\Data\MagicLoader\. MagicLoader reads those JSONs at game start and merges them into the live record set. For non-English speakers, the localization strings can be replaced with your language of choice.

  • Required for custom dungeons to load correctly and for localization strings to work (books, creature names, item names, spell names, location names, quest dialog, etc.).

TesSyncMapInjector (UE4SS Lua mod)

OOORF's …\ObvData\Data\SyncMap\Oscuro's_Oblivion_Overhaul.ini is a list of <TES4 FormID hex>=<UE5 SoftObjectPath> lines. TesSyncMapInjector consumes this at load time and rebinds each FormID to its UE5 asset path — the bridge that lets ESP records point at UE5 meshes/blueprints.

  • Required to avoid invisible or missing assets and prevent game crashes when NPCs and creatures spawn. Also required for any new items like the bundled Obsidian set.

UE4SS

The Unreal Engine 4 / 5 Scripting System. A loader for native DLL and Lua mods inside Unreal games.

UE4SS — "UE4SS new", v3.0.1-1164 or later (required from alpha92). Get it from the UE4SS Nexus page, under Update files, the file named "UE4SS new" (uploaded 10 Oct 2026). It installs over an existing UE4SS: overwrite the files.

The "UE4SS stable" main file (3.0.1.a) is not supported from alpha92. OOORF's RAX mod contains a native DLL built for one exact UE4SS version: the alpha92 RAX DLL is not safe on the old UE4SS, and the alpha91 RAX DLL is not safe on the new one. The UE4SS page warns that some older UE4SS mods may not work with "UE4SS new"; TesSyncMapInjector v0.1.8 and MagicLoader v2.9 work with it.

  • Required by TesSyncMapInjector (Lua) and RAX — both essential for normal play (SyncMap binding and custom-map loading respectively).
  • Also used by the optional test mods Begone (development test recording / debugging) and OOO_REFRFix (save migration for users with existing saves on older alpha releases), if you deploy them.

Bundled UE4SS mods — required for normal play

This ships inside the OOORF archive — don't install separately, but it DOES require UE4SS to be installed first.

Mod (under …\Binaries\Win64\ue4ss\Mods\) Role
RAX/ Allows loading of custom UE5 maps (the new L_*_Map dungeons). Native DLL (dlls/main.dll) plus Lua glue. The alpha92 DLL is built for "UE4SS new" v3.0.1-1164. Do not use it with any other UE4SS version.

Optional test UE4SS mods (manual deploy)

These run on UE4SS too, but are not required for normal play. They exist to support the OOORF alpha-testing workflow. From alpha92 they are not installed by default: they ship under OblivionRemastered\alpha92_test_optional\ with their install tree intact. To use one, copy its folder from alpha92_test_optional\Binaries\Win64\ue4ss\Mods\ into OblivionRemastered\Binaries\Win64\ue4ss\Mods\. Installing alpha92 over alpha91 does not remove the alpha91 copies; delete Mods\Begone\ and Mods\OOO_REFRFix\ unless you want them.

Mod (under …\Binaries\Win64\ue4ss\Mods\) Role
Begone/ Test recording and debugging. Originally Begone hid UE5 ghost objects at runtime per Config/OscurosOblivionOverhaul.json; alpha90 baked that suppression into the map paks. From alpha92 Begone is log-only: it suppresses nothing. Its remaining use is capturing per-cell object inventories during alpha-test walkthroughs and checking suppression coverage when new map paks are built.
OOO_REFRFix/ Save-file migration helper. Patches OOO reference placements that need runtime correction; see Scripts/spawn_deltas.lua. Only needed if you have existing saves carrying OOO references from older alpha releases.
